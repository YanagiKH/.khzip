# `.khzip` Container Format v1

This document describes the implemented version 1 container. All integers are little-endian. Readers must reject unsupported versions, impossible lengths, unsafe paths, malformed record offsets, authentication failures, and hash mismatches.

## File layout

```text
+----------------------+ 0
| Fixed header (128 B) |
+----------------------+
| Chunk record 0       |
+----------------------+
| Chunk record 1       |
+----------------------+
| ...                  |
+----------------------+
| Encrypted manifest   | <- header.index_offset
+----------------------+
| Trailer (48 B)       |
+----------------------+
```

## Fixed header

| Offset | Size | Field |
|---:|---:|---|
| 0 | 8 | ASCII magic `KHZIP001` |
| 8 | 2 | format version |
| 10 | 1 | archive format ID |
| 11 | 1 | compression mode ID |
| 12 | 4 | flags |
| 16 | 16 | KDF/archive salt |
| 32 | 16 | primary nonce prefix |
| 48 | 16 | secondary nonce prefix |
| 64 | 8 | manifest record offset |
| 72 | 8 | unique chunk count |
| 80 | 8 | entry count |
| 88 | 40 | reserved, must currently be zero |

Flags:

- bit 0: encrypted
- bit 1: double encrypted
- bit 2: device bound

## Record header

Every record starts with a 64-byte header.

| Offset | Size | Field |
|---:|---:|---|
| 0 | 4 | `KHR1` |
| 4 | 1 | kind: chunk=1, manifest=2 |
| 5 | 1 | codec: none=0, zstd=1, brotli=2, lzma2=3 |
| 6 | 2 | record flags |
| 8 | 8 | monotonic ordinal |
| 16 | 8 | decompressed length |
| 24 | 8 | stored payload length |
| 32 | 32 | BLAKE3 identity of decompressed data |

The record payload follows immediately. Encrypted payloads include the Poly1305 authentication tag generated by XChaCha20-Poly1305.

## Nonces and associated data

A nonce is the 16-byte random archive prefix followed by the 8-byte little-endian record ordinal. Ordinals must never repeat inside one archive. The immutable header prefix and record metadata are authenticated as associated data. `.khaz` applies a second independent XChaCha20-Poly1305 layer using a domain-separated key, a second random nonce prefix, and a second associated-data domain.

## Password KDF

Version 1 uses Argon2id v1.3 with:

- memory: 128 MiB
- iterations: 3
- lanes: 1
- output: 32 bytes

The base output is expanded into domain-separated primary and secondary AEAD keys with BLAKE3's key derivation mode.

## Manifest

The manifest is serialized with Postcard, compressed with Zstandard, and encrypted for encrypted formats. It contains:

- version, archive format, and compression mode
- creation time
- file and directory entries
- normalized relative paths
- file sizes, Unix modes, and modification times
- ordered per-file chunk IDs
- unique chunk IDs, offsets, and lengths
- original and unique byte counts
- BLAKE3 Merkle root

Symbolic links and special files are not represented in v1.

## Trailer

| Offset | Size | Field |
|---:|---:|---|
| 0 | 8 | `KHTRLR01` |
| 8 | 8 | manifest offset |
| 16 | 32 | BLAKE3 hash of every preceding byte |

The trailer detects accidental truncation and corruption. It is not a signature and does not provide malicious-tampering resistance for unencrypted archives.

## Split `.khx`

A `.khx` archive is the exact container byte stream divided into numbered files:

```text
name.khx.001
name.khx.002
name.khx.003
```

The first part is passed to the reader. Parts are concatenated in order before normal parsing and verification. Part splitting itself does not add confidentiality.

## Forward compatibility

Header bytes 88-127 are reserved. Future recipient key slots, HPKE/X25519 envelopes, and ML-KEM hybrid slots require a new versioned extension structure. A reader must not infer unsupported cryptography from an extension name or flag.
